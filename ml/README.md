# ML и Buddy MCP

Из одного образа запускаются два сервиса. `ml` обслуживает чат и индексацию
на FastAPI, а `buddy-mcp` предоставляет инструменты для демо через MCP
(Model Context Protocol). Оба используют PostgreSQL.

Из корня проекта, с настроенным [`.env`](../.env.example):

```bash
docker compose up -d --build ml buddy-mcp
docker compose logs -f ml buddy-mcp
```

Оба сервиса входят и в обычный `make up`. Порты ML и MCP доступны внутри
Docker-сети. При сборке образа скачивается ONNX-модель multilingual-e5-small.
Для генерации и выбора инструментов нужны `OPENAI_BASE_URL`, `OPENAI_API_KEY`
и `OPENAI_CHAT_MODEL`. `MESSAGES_PER_USER` из Compose задаёт окно истории,
`DOCUMENTS_TO_CONTEXT` — число фрагментов базы знаний.

| Маршрут ML | Назначение |
| --- | --- |
| `GET /health` | Проверка ML-процесса |
| `POST /documents` | Обновляет индекс по `document_id` и статусу `added`, `modified` или `deleted` |
| `POST /analyze` | Принимает `user_id`, `message_id` и опциональный `stream` |

При индексации ML разбивает текст на фрагменты и сохраняет их векторы в
`document_chunks`. В чате он читает историю пользователя, строит вектор вопроса
и добавляет ближайшие фрагменты из pgvector в контекст модели.

## Как работает MCP

- ML подключается к `BUDDY_MCP_URL` (в Compose обычно `http://buddy-mcp:8000/mcp`)
  по Streamable HTTP. Он передаёт ID пользователя в `X-Buddy-User-ID` и
  `BUDDY_MCP_TOKEN` как Bearer-токен.
- ML получает список инструментов, фильтрует его по разрешённым именам и
  передаёт схемы модели. Модель может искать по тестовой базе знаний,
  проверять доступы и состояние PR, готовить черновики заявок на доступ,
  ревью и отсутствие. Результаты инструментов попадают в контекст ответа.
- Черновик содержит команду `Подтверждаю <id> <версия>`. Её обрабатывает ML
  напрямую и использует отдельный `BUDDY_MCP_SUBMIT_TOKEN` для отправки.
  Сервис хранит черновики и статусы в `demo_actions`. Действия имитируются
  локально в демо.
- Для потокового чата после выбора инструментов ML делает отдельный запрос
  на финальную генерацию с результатами инструментов. Backend передаёт
  события SSE `token`, `done` и `error` в браузер. Ответы на команды и
  готовые черновики формируются сразу.

Пустой `BUDDY_MCP_URL` отключает инструменты. Если адрес задан и MCP недоступен,
чат может вернуть 502 при работающем `/health`. Пустой токен отправки отключает
подтверждение действий. Код сервера и инструментов в [src/mcp](src/mcp).

## Тесты

Из корня проекта, в отдельном окружении Python 3.12:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r ml/requirements-test.txt
.venv/bin/python -m pytest ml/tests --cov=ml/src --cov=ml/health
```
