# Тесты backend

Все Go-тесты находятся в этой директории. Код приложения не подменяется.
HTTP-обработчики проверяются через публичные функции
и регистрацию маршрутов, PostgreSQL-запросы — на настоящей базе с миграциями проекта,
ML — через локальные HTTP-серверы.

Нужны Go версии из `../go.mod` и отдельная тестовая база PostgreSQL 17.
Роль PostgreSQL должна иметь право создавать и удалять схемы. Каждый тест создаёт
свою схему с уникальным именем и удаляет её после завершения. Используй отдельную
базу для тестов.

Из директории `backend`:

```bash
docker run --rm --name giga-buddy-test-db \
  -e POSTGRES_USER=postgres -e POSTGRES_PASSWORD=postgres \
  -e POSTGRES_DB=giga_buddy_test -p 55432:5432 -d postgres:17

# Дождись, пока база начнёт принимать подключения:
docker exec giga-buddy-test-db pg_isready -U postgres -d giga_buddy_test

export TEST_DATABASE_URL='postgres://postgres:postgres@127.0.0.1:55432/giga_buddy_test?sslmode=disable'
bash tests/run.sh

# После работы:
docker stop giga-buddy-test-db
```

`tests/run.sh` запускает тесты с детектором гонок и проверяет минимум **90% покрытия
операторов всего Go-модуля**. В расчёте участвует также `cmd/server`, хотя его
`main` напрямую не вызывается. Пакеты и файлы из отчёта не исключаются.

Отчёты создаются в `backend/coverage/`: `coverage.out`, `summary.txt`,
`coverage.html`. Эту же команду можно использовать в CI.

Покрываются конфигурация, JWT и refresh-токены, middleware, профиль пользователя,
login/refresh/logout, cookies, история и поток чата, ошибки ML, обрывы соединений,
запросы пользователей и сессий, лимит истории и откат транзакций. Негативные тесты
login проверяют, что при неверных учётных данных токены не выдаются.

Тесты документов проверяют все семь категорий, фильтрацию и лимит списка, пустой
результат, чтение Markdown без изменений, удалённые и отсутствующие документы,
обязательную авторизацию, валидацию параметров и текст ошибок в JSON, ошибки БД
и отмену контекста. Для них применяются миграции таблицы документов, включая поля
Google Drive. Порядок списка не фиксируется: API не гарантирует сортировку.

Проверка запуска сервера временно занимает порт 8080, чтобы `Run` завершился с
ошибкой привязки и не оставил работающий HTTP-сервер. Остальные HTTP-серверы
используют случайные свободные порты. Часовой фоновый цикл очистки и недостижимые
с текущими типами аргументов ошибки криптографических функций не покрыты полностью.
